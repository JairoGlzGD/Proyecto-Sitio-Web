01 / FUNDAMENTOS

¿Qué es la Máscara de Subred de Longitud Fija (FLSM)?

FLSM (Fixed Length Subnet Mask) es una técnica de subneteo en IPv4 donde una red principal se subdivide en varias subredes que comparten exactamente la misma máscara de subred y la misma longitud de prefijo CIDR. Cada subred resultante tiene exactamente la misma capacidad total de direcciones IP.

=

Tamaño Uniforme

Todos los bloques contienen el mismo número de direcciones IP totales y útiles.

/

Máscara Invariable

El prefijo CIDR calculado se aplica sin excepción a todas las subredes generadas.

+

Salto Regular

El incremento de direcciones de red (número mágico) es constante y predecible.

¿Cuándo usar FLSM vs. VLSM? FLSM es ideal cuando las subredes o departamentos de una organización requieren capacidades similares de equipos (por ejemplo, aulas de cómputo con 30 puestos cada una). Cuando los segmentos tienen diferencias extremas (por ejemplo, enlaces punto a punto de 2 hosts frente a redes de 500 hosts), se utiliza VLSM (Variable Length Subnet Mask) para optimizar el espacio de direcciones.

02 / VOCABULARIO TÉCNICO

Conceptos Previos Esenciales

Antes de aplicar el procedimiento aritmético, familiarízate con las seis variables fundamentales del direccionamiento IPv4:

Dirección IPv4
Identificador numérico lógico de 32 bits, estructurado en cuatro octetos de 8 bits separados por puntos (ejemplo: 192.168.5.10).
Prefijo CIDR
Notación que especifica la cantidad de bits pertenecientes a la porción de red (ejemplo: /24 indica 24 bits de red y 32 − 24 = 8 bits para hosts).
Dirección de Red
La primera dirección del bloque. Tiene todos los bits de host en cero (0) y sirve para enrutar el tráfico hacia esa subred. No puede asignarse a un dispositivo terminal.
Dirección de Broadcast
La última dirección del bloque. Tiene todos los bits de host en uno (1) y se utiliza para enviar mensajes a todos los hosts de esa subred. No puede asignarse a un host.
Hosts Utilizables
Rango de direcciones situadas estrictamente entre la dirección de red y la de broadcast. Su capacidad se calcula con la fórmula clásica 2h − 2.
Bits Prestados (n)
Bits tomados de la porción original de host y reasignados a la porción de red para generar 2n subredes independientes.

Alcance técnico: Este material trata subredes ordinarias con prefijos hasta /30. Los prefijos /31 (enlaces punto a punto según RFC 3021) y /32 (host individual) poseen reglas especiales y quedan fuera del alcance didáctico básico.

03 / PROCEDIMIENTO PASO A PASO

El Método de los Cinco Pasos

Aprende el procedimiento estándar de cálculo utilizando el caso de estudio oficial: Dividir la red 192.168.5.0/24 para obtener al menos 5 subredes con hasta 30 hosts útiles cada una.

1Requerimientos 2Bits Prestados 3Nueva Máscara 4Salto y Redes 5Rangos y Broadcast

PASO 1 DE 5 · ANÁLISIS DE REQUERIMIENTOS

Identifica los Datos Base y las Necesidades

Recopila los parámetros iniciales del problema antes de realizar cualquier operación matemática:

  • Red original: 192.168.5.0/24 (Clase C privada).
  • Subredes requeridas (N): Al menos 5 segmentos independientes.
  • Capacidad requerida (H): Hasta 30 hosts útiles por segmento.
  • Bits disponibles para host originalmente: 32 − 24 = 8 bits.
Principio FLSM: Dado que todas las subredes tendrán el mismo tamaño, el cálculo debe dimensionarse considerando el segmento que requiera la mayor cantidad de hosts.

PASO 2 DE 5 · ARITMÉTICA DE BITS

Calcula los Bits Prestados (n)

Encuentra el menor número entero n tal que satisfaga la inecuación de potencias: 2n ≥ N (subredes requeridas).

Para n = 1: 21 = 2 subredes (Insuficiente para 5)

Para n = 2: 22 = 4 subredes (Insuficiente para 5)

Para n = 3: 23 = 8 subredes (¡Cumple el requisito! Se prestan 3 bits de la porción de host)

Al prestar 3 bits, el nuevo prefijo CIDR será: CIDR = 24 + 3 = /27.

Los bits restantes para host serán: h = 8 − 3 = 5 bits.

PASO 3 DE 5 · MÁSCARA Y VALIDACIÓN DE CAPACIDAD

Determina la Máscara y Valida la Capacidad

Convierte el nuevo prefijo /27 a notación decimal punteada y comprueba que los bits de host satisfagan el requerimiento.

Desglose del 4.° octeto en binario: 11100000

Valor decimal: 128 + 64 + 32 = 224

Máscara de subred resultante: 255.255.255.224

Comprobación de hosts útiles: 2h − 2 = 25 − 2 = 32 − 2 = 30 hosts utilizables

Validación exitosa: 30 ≥ 30 hosts. Si el requerimiento hubiera sido de 31 hosts, un prefijo /27 no habría sido suficiente y la red base /24 no podría haber abastecido 5 subredes con FLSM.

PASO 4 DE 5 · NÚMERO MÁGICO Y REDES

Calcula el Salto (Número Mágico) y Enumera las Redes

El salto constante entre subredes consecutivas se obtiene restando el valor del octeto modificado a 256:

Fórmula del Salto: Salto = 256 − Máscara del octeto modificado

Salto = 256 − 224 = 32 (aplicado en el 4.° octeto)

Secuencia aritmética de las ocho direcciones de red:

.0→ .32→ .64→ .96→ .128→ .160→ .192→ .224

Las 5 primeras subredes cubren los 5 segmentos requeridos; las subredes 6, 7 y 8 quedan como reserva estratégica.

PASO 5 DE 5 · DELIMITACIÓN DE RANGOS

Calcula el Rango de Hosts y la Dirección de Broadcast

Para cada bloque de subred, las direcciones se delimitan mediante tres reglas fijas:

  • Primer host utilizable: Dirección de red + 1
  • Dirección de broadcast: Siguiente dirección de red − 1 (o Red + Salto − 1)
  • Último host utilizable: Broadcast − 1

Ejemplo con la Subred 3: Red = 192.168.5.64/27

Primer Host: 64 + 1 = 192.168.5.65

Broadcast: 64 + 32 − 1 = 192.168.5.95

Último Host: 95 − 1 = 192.168.5.94

07 / PREVENCIÓN DE ERRORES Y GLOSARIO

Errores Frecuentes en el Subneteo FLSM

Contar solo las subredes y olvidar los hosts

Calcular 2n ≥ N no garantiza que la subred cumpla con los hosts requeridos. Siempre verifica que 2h − 2 ≥ Hosts requeridos.

Confundir la IP de Red con el Primer Host

La dirección de red (ej. .64) identifica al bloque. El primer host asignable es siempre la dirección inmediata siguiente (ej. .65).

Asumir que el salto es siempre 32

El salto de 32 corresponde exclusivamente al prefijo /27. Para un /26 el salto es 64, para un /28 es 16, etc.

Ignorar las subredes sobrantes

Si solicitas 5 subredes y prestas 3 bits, se generan 8 subredes matemáticas. No las descartes: deben registrarse como subredes de reserva.

Glosario Técnico Interactivo

Es el tamaño del bloque de direcciones asignadas a cada subred. Se calcula restando a 256 el valor decimal del octeto donde ocurrió la división en la máscara de subred (256 − Máscara del octeto). Indica de cuánto en cuánto aumentan las direcciones de red consecutivas.
Por norma del protocolo IPv4 (RFC 791), la primera dirección del bloque tiene todos sus bits de host en 0 y está reservada para identificar a la red misma. La última dirección tiene todos sus bits de host en 1 y está reservada para la difusión o broadcast de esa subred. Por lo tanto, no pueden configurarse en ninguna tarjeta de red.
En FLSM todas las subredes tienen la misma máscara y la misma cantidad de hosts. En VLSM (Máscara de Subred de Longitud Variable), se pueden aplicar máscaras distintas a cada subred (por ejemplo, /26 para 60 hosts y /30 para enlaces seriales de 2 hosts), evitando el desperdicio masivo de direcciones IP.

09 / DOCUMENTACIÓN TÉCNICA OFICIAL

Fuentes Normativas y Referencias

Los estándares y principios matemáticos implementados en este recurso se fundamentan en las siguientes publicaciones del IETF y referencias técnicas:

  • RFC 791: Internet Protocol (IP Specification) ↗

    Estándar original de DARPA que define la arquitectura de 32 bits, encabezados y direccionamiento de IPv4.

  • RFC 950: Internet Standard Subnetting Procedure ↗

    Procedimiento formal estandarizado para la creación de subredes y máscaras a nivel de capa de red.

  • RFC 1878: Variable Length Subnet Table For IPv4 ↗

    Tablas canónicas de prefijos CIDR, máscaras de subred, capacidades de bloques y rangos de hosts útiles.

  • RFC 3021: Using 31-Bit Prefixes on IPv4 Point-to-Point Links ↗

    Documento de referencia para el tratamiento especial de enlaces seriales punto a punto sin dirección de broadcast.
